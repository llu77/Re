# صياغة — حملات المنتجات

تطبيقٌ مستقلّ عن منصّة التأهيل. يُجهّز فيه المستخدم حملةً لمنتج بأزرارٍ عادية
يضغطها بتتبّع العين في iOS:

1. يختار صورة المنتج. يعيد الخادم ترميزها فيزيل موقع التقاطها وكل بياناتها الوصفية.
2. يقترح Claude (`claude-opus-5-5`) عنواناً ووصفاً بالعربية. لا يُرسل إليه إلا الصورة ونصّ المنتج، ولا شيء عن صاحبه.
3. يوافق المستخدم، أو يطلب تعديلاً بخياراتٍ جاهزة وملاحظةٍ اختيارية، أو يعود إلى نسخةٍ سابقة بلا استدعاءٍ جديد.
4. يحدّد الميزانية الإجمالية والمدّة بأزرارٍ جاهزة وخطوات، بلا سحب، ويرى المبلغ بالكلمات.
5. يعتمد الحملة بخطوتين متباعدتين.
6. تصير الحملة **جاهزة للتسليم**: يشاركها أو ينسخها أو ينزّل صورتها. **لا يُنشر شيءٌ ولا يُدفع أيّ مبلغ.**

لا شيفرة كاميرا ولا تتبّع نظر في التطبيق: نظام iOS يتتبّع العين على الجهاز،
والصفحة لا ترى إلا نقرات.

`tests/architecture/test_separation.py` تفرض الفصل في الاتجاهين.

## بوابة الإصدار 0 — قبل أيّ استعمال

التطبيق كلّه يقوم على افتراضٍ واحد لم يُتحقّق منه بعد: **أن تتبّع العين في iOS
يضغط محتوى الويب**. صفحة `/probe/` («فحص الإدخال») تقيس ذلك على الجهاز نفسه،
ولا ترسل شيئاً (CSP: `connect-src 'none'`) ولا تخزّن شيئاً.

الإجراء، على iPhone 12 أو أحدث بنظام iOS 18 أو أحدث، بيد مستخدمٍ معايِر لتتبّع العين مع تفعيل «المكوث»:

1. افتح `https://<الأصل>/probe/` في Safari، وأكمل الأقسام التسعة بالنظر.
2. أضف الصفحة إلى الشاشة الرئيسية، وافتحها منها، وأعد الأقسام.
3. في كل تشغيل: «انسخ النتيجة» والصق النصّ في الجدول أدناه.

يُعدّ الويب صالحاً لوضعٍ ما إذا نجح فيه «الضغط بالنظر يصل الصفحة» و«اختيار صورة
بنوعٍ مقبول». وإن فشلا في الوضعين فلا يُستعمل التطبيق، والقرار التالي (تطبيقٌ
أصلي مثلاً) قرارٌ مستقلّ.

وتُسجَّل معها: هل يعيد النظام الضغط دون تحريك النظر؛ وهل الأزرار السفلية ظاهرةٌ
كاملةً فوق شريط Safari (ولا سيّما iOS 26)؛ وهل يقترح Safari «كلمة مرور قوية»
في صفحة التفعيل ويحفظها؛ وهل يملؤها Face ID مع تشغيل تتبّع العين؛ وهل تعمل
المشاركة والنسخ؛ ورفع صورٍ حقيقية من الكاميرا (HDR مفعّل، بصيغتي HEIC و«الأكثر
توافقاً»).

## التشغيل

```bash
# الأدوار تُنشأ قبل الترحيل ولا يُنشئها الترحيل، ولا يحمل أيٌّ منهما صلاحيةً تتجاوز العزل:
#   CREATE ROLE eyework_owner LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE NOCREATEDB PASSWORD '…';
#   CREATE ROLE eyework_app   LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE NOCREATEDB PASSWORD '…';
#   CREATE DATABASE eyework OWNER eyework_owner;
# في التطوير: bash eyework/scripts/dev_db.sh start

pip install -r eyework/requirements.txt

export EYEWORK_OWNER_DATABASE_URL=postgresql://eyework_owner:…@db/eyework   # الترحيل وأداة المشغّل فقط
python -m eyework.migrations.run up

export EYEWORK_APP_DATABASE_URL=postgresql://eyework_app:…@db/eyework       # خادم الويب
export EYEWORK_LOGIN_KEY=$(python -c "import base64,secrets;print(base64.b64encode(secrets.token_bytes(32)).decode())")
export EYEWORK_ANTHROPIC_API_KEY=…
export EYEWORK_PUBLIC_ORIGIN=https://<الأصل>

uvicorn --factory eyework.web.app:create_app --workers 1 --no-access-log \
        --proxy-headers --forwarded-allow-ips <عنوان الوكيل>
```

- **عاملٌ واحد.** حدود الدخول والرفع في ذاكرة العملية؛ سقوف الذكاء الاصطناعي في القاعدة فتصمد مع أيّ عدد.
- **`--no-access-log`، وسجلّ الوصول في الوكيل معطّل أو مقتطع.** سطر الوصول (العنوان والمسار والوقت) يكفي لاستنتاج من يستخدم التطبيق.
- **مهلة القراءة في الوكيل ≥ 210 ثوانٍ.** كتابة النصّ قد تستغرق حتى نحو 190 ثانية في أسوأ الأحوال؛ وإن قطع الوكيل الطلب قرأت الواجهة الحملة من جديد ولم تفترض شيئاً.
- يرفض التطبيق الإقلاع إن كان دور قاعدته superuser أو BYPASSRLS أو مالكاً لجدول أو قادراً على قراءة الهوية.

## أداة المشغّل

```bash
python -m eyework.admin create-user --login ali@example.sa          # يطبع رابط تفعيلٍ صالحاً 72 ساعة
python -m eyework.admin reissue-activation --login ali@example.sa   # الاسترداد الوحيد: رابطٌ جديد، والقديم يُغلق
python -m eyework.admin deactivate --login ali@example.sa
python -m eyework.admin delete-user --login ali@example.sa --confirm-delete-all-data
python -m eyework.admin purge                                       # يومياً من مجدول النظام
```

- **الحسابات بدعوة.** لا تسجيل ذاتي ولا بريد يخرج من التطبيق. يسلّم المشغّل الرابط بنفسه، ويحفظ صلة اسم الدخول بصاحبه **خارج النظام**؛ القاعدة لا تخزّن الاسم، بل HMAC له.
- **اسم الدخول** من `a-z 0-9 . _ @ + -`: التوحيد لا يجمع «أ» و«ا» ولا «ى» و«ي».
- **`EYEWORK_LOGIN_KEY` يُحفظ مع النسخ الاحتياطية.** فقده يُغلق كل الحسابات، وتغييره يعني إعادة دعوة الجميع.
- يُفعَّل الحساب في Safari؛ والتطبيق المضاف إلى الشاشة الرئيسية له ملفّات ارتباطٍ مستقلّة، فيدخل المستخدم فيه مرةً واحدة بتعبئة سلسلة المفاتيح.

## الاحتفاظ والنسخ الاحتياطي

| ما | متى يُحذف |
|---|---|
| صورة حملةٍ أُلغيت أو سُحبت | فوراً، في المعاملة نفسها |
| حملة جاهزة أو ملغاة | بعد 90 يوماً (`purge`) |
| حملة لم تكتمل | بعد 30 يوماً من آخر تعديل (`purge`) |
| الجلسات والرموز المنتهية | بعد 30 يوماً (`purge`) |
| حساب | `delete-user` يحذف كل ما يتبعه |

النسخ الاحتياطي بدور المالك يحتاج `pg_dump --enable-row-security`: الجداول تحت
`FORCE ROW LEVEL SECURITY`.

## ما يغادر بنيتنا

صورة المنتج بعد إعادة ترميزها، ونصّ المنتج (النسخة السابقة وخيارات التعديل
وملاحظة المستخدم إن كتبها) — إلى Anthropic وحدها، بمفتاحٍ خاصٍّ بهذا التطبيق.
لا معرّف ولا اسم ولا وصف لحال المستخدم. يُوصى بمساحة عملٍ مستقلّة بحدّ إنفاق،
وبعدم الاحتفاظ بالبيانات (ZDR) إن أُتيح، لأن الصورة والملاحظة تُحفظان لدى
المزوّد مدّته الافتراضية وإلا.

## افتراضاتٌ معلَنة

- **الصورة ليست «إطارات كاميرا».** قاعدة المنصّة («إطارات الكاميرا تُعالج على الجهاز ولا تُخزَّن ولا تُرسل») تخصّ الكاميرا تفتحها الشيفرة. هنا لا تفتح الشيفرة كاميرا أبداً (`Permissions-Policy: camera=()`، بلا `capture` ولا `getUserMedia`)؛ لكن منتقي الملفات في iOS يعرض «التقاط صورة» من النظام. صورة المنتج يختارها المستخدم عمداً أو يلتقطها بنفسه، فتُعامل محتوىً يقدّمه هو، وتُخزَّن وتُرسل إلى النموذج. **هذا الافتراض يحتاج موافقة المالك صراحةً.**
- الميزانية **إجمالية** بالريال السعودي، من 36 قيمة بين 50 و5,000. المدّة من يومٍ إلى 30. المبلغ اليومي للعرض فقط.
- «جاهزة للتسليم» تعني ملخّصاً ثابتاً يُشارَك. لا نشر في أيّ منصّة إعلانية ولا دفع.
- النصّ بالعربية الفصحى لجمهورٍ سعودي.

## ما لم يُبنَ، ولماذا

- **مراجعة الحسابات.** ذُكرت مثالاً، بلا تعريفٍ لما يُراجَع ولا لما يُسلَّم، وهي فئة خطرٍ أخرى (بيانات مالية لأطرافٍ ثالثة). بناؤها يعني اختراع متطلبات.
- **النشر الإعلاني والدفع وحسابات أصحاب العمل.** تحتاج بيانات اعتمادٍ لطرفٍ ثالث وقرارات تجارية.
- **مفاتيح المرور (passkeys).** تحتاج اعتماديةً جديدة؛ كلمة المرور القوية مع سلسلة المفاتيح وFace ID تكفي الآن.

## الاختبارات

```bash
bash eyework/scripts/dev_db.sh start
export EYEWORK_TEST_DATABASE_URL=$(bash eyework/scripts/dev_db.sh dsn eyework_test)
EYEWORK_OWNER_DATABASE_URL=$EYEWORK_TEST_DATABASE_URL python -m eyework.migrations.run up
python -m pytest eyework/tests -q
```

`unit/` و`architecture/` بلا قاعدة؛ `db/` و`api/` على قاعدة اختبارٍ اسمها ينتهي
بـ`_test` (يرفض الملفّ غيرها)؛ `ui/` في Chromium. وفي CI يجعل
`EYEWORK_REQUIRE_DB=1` و`EYEWORK_REQUIRE_BROWSER=1` غيابَ أيٍّ منهما فشلاً لا
تجاوزاً.
